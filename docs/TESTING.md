# Try it yourself

Three ways to test the platform with realistic data, from easiest to most
technical. All three use the same sample files.

## 0. The sample data

`samples/` holds a fictional two-store bakery, **Sunrise Bakery**, over two
years (generated by `scripts/make_sample_data.py`, fixed seed so everyone gets
identical files):

| File | What's in it | Good for trying |
|---|---|---|
| `sales.csv` | ~18,000 order lines: date, product, category, store, quantity, price, amount, payment, **order type** (in-store / online pickup / delivery / catering), **customer type** and **age group** | Dashboard KPIs + filters, missing-value fills, trends, models |
| `customers.csv` | 400 customers with names, emails, phones, cities, customer type, age group | PII scan, data dictionary, enrichment |
| `feedback.csv` | 900 satisfaction (CSAT 1–5) and NPS (0–10) responses | Averages dashboard, hypothesis tests |
| `expenses.csv` | Monthly rent, payroll, ingredients, utilities, marketing | Expense trends |
| `quickbooks_customers.csv` | The same customers as a QuickBooks export — **no customer_id**, names spelled differently | Fuzzy matching |

There's a real story to find: growth over two years, busier weekends,
a November–December holiday bump, a price increase on June 1, 2025, online
orders growing from about 12% to 28%, delivery launching March 1, 2025, and some
deliberately messy rows (duplicates, a blank row, stray spaces). Walk-ins have
no `customer_id` or `age_group` (about 31% missing each) — good for trying the
missing-value advice.

Regenerate (e.g. to move the dates so "month to date" is current):

```bash
python scripts/make_sample_data.py --end 2026-10-31
```

## 1. In the web app (no code)

1. Start both servers ([GETTING_STARTED.md](GETTING_STARTED.md)):
   `uvicorn api.main:app --reload` and, in `web/`, `npm run dev`.
2. Open http://localhost:3000 → **Start as a guest** → **Business** → pick a
   **company size** (LinkedIn's bands, e.g. 11–50 employees) and an industry →
   **Files on my computer** → upload `samples/sales.csv` → **Clean my data**.
3. On **Your data, cleaned**:
   - The tiles show rows, **fields (13)**, duplicates removed and % missing; the
     preview shows the first 5 rows.
   - **Missing values by column:** `customer_id` and `age_group` are flagged
     **Review** (31% missing). `customer_id` has no fill options (it's an ID — a
     blank means a walk-in). For `age_group`, choose **Fill with mode** →
     **Apply changes**: the tile now says "5,584 filled". Try **Remove this column**
     too. **Use our suggestions** only fills small gaps (under 20%) and removes 90%+
     columns, so on this file it changes nothing — by design.
4. Scroll to **Explore your data**. Only Data Cleaning is included at first:
   - **Dashboard** is locked → **Add Data Visualization**. You'll see Total amount
     and Transactions, then one card + chart per top **order type** (In-store,
     Online pickup, Delivery, Catering). Use the **time bar floating at the bottom**:
     Last 4 weeks / Last 3 months / Last year / Month to date / Year to date /
     All time, and Day / Week / Month over month. Filter by **Customer Type**,
     **Age Group** or **Store** (e.g. Wholesale). **Download dashboard (HTML)**
     saves a stand-alone copy you can email.
   - **Run a skill** — the dropdown lists only unlocked services' skills; the others
     are 🔒 badges with their price. Click **Data Exploration & Analysis · Add**, then
     try *Key trends* (value column = amount) or *Forecasts & predictive models*
     after adding Data Science & ML.
5. Upload `samples/sales.csv` + `samples/customers.csv` + `samples/quickbooks_customers.csv`
   together to see multi-file grouping, a shared-ID link (🔗) and a fuzzy link (≈).

### Signup rules and location

On **Create an account**, try: a lowercase first name (it's capitalized as you
type), a digit in a name, `name@example` as the email, an emoji in the business
name, or the same email for you and a team member — each gets a clear message
under the field. Accents (José, García-López, Nguyễn) are fine. **Location** is
optional: type "decat" and pick a city with ↓ and Enter. Signing up twice with
the same email (in any capitalization) is refused.

### Small files (30-row minimum)

Upload a file with fewer than 30 rows (e.g. the first 10 lines of
`samples/sales.csv`): it's cleaned and downloadable, but a banner explains that
the dashboard and analysis skills need at least 30 rows, and only the cleaning
tools are offered.

### The signed-in workspace

1. On the home page, click **Create an account** (under "Start as a guest"), sign up
   with any email and a password (8+ characters), and you land in **/app**.
   (As the consultant — all seven services, the database load and
   consultations — follow [RUN_THROUGH.md](RUN_THROUGH.md).)
2. The left pane shows 🧹 Data Cleaning on top (always included) and every other
   service grayed out with an **i** button — click one to see what it adds, its price,
   and how to get it.
3. Choose `samples/sales.csv`. Click the grayed **📊 Dashboard** → **Add Data
   Visualization to my plan**: Dashboard moves to the top of the pane and opens.
4. The time controls are two panels at the bottom: ranges above, comparisons
   below. Make the window narrow (or open it on a phone): they switch to
   **4W 3M 1Y MTD YTD All** and **DoD WoW MoM**.
5. Each service page has a **Skill** menu at the top and opens on its default:
   the cleaning report, the dashboard, or the service's primary skill, which runs
   by itself (e.g. *Dataset profiling* for Data Exploration & Analysis). Skills
   that need an option first (*Forecasts & predictive models* needs a target column)
   open on their form with a hint.
6. To see the time bar adapt, use **Change files** with a short extract — e.g. the
   last 7 days of `sales.csv` shows only "Last week" and "Day over day".
7. Services picked in the guest questionnaire ("Your needs") are already on the
   plan if you create the account at the wizard's download step.

## 2. From the command line

```bash
python -m data_skills list                                   # all 30 skills by category
python -m data_skills describe build-dashboard               # a skill's options
python -m data_skills run build-dashboard samples/sales.csv  # -> outputs/build-dashboard/html_dashboard.html
python -m data_skills run build-dashboard samples/sales.csv --param 'filters={"customer_type": "Wholesale"}'
python -m data_skills run data-cleaning samples/sales.csv --raw --param 'column_actions={"age_group": "mode"}'
python -m data_skills run trend-analysis samples/sales.csv --param value_column=amount --param segment_column=category
python -m data_skills run ask-your-data samples/sales.csv --param "question=total amount by store"
python -m data_skills run er-diagram samples/sales.csv samples/customers.csv samples/feedback.csv
python -m data_skills run data-reporting samples/sales.csv --param title="Sunrise Bakery"
python -m data_skills run setup-data-workspace samples/*.csv --param db_path=outputs/workspace.db
```

The summary and findings print in the terminal; tables (CSV), reports,
SQL, diagrams and `result.json` are saved to `outputs/<skill>/` (git-ignored).
Files are cleaned first unless the skill needs the raw upload (or you pass `--raw`).

Open the dashboard file in your browser:

```bash
open outputs/build-dashboard/html_dashboard.html        # macOS
xdg-open outputs/build-dashboard/html_dashboard.html    # Linux
start outputs/build-dashboard/html_dashboard.html       # Windows
```

## 3. Through the API

With the API running, open http://localhost:8000/docs → **skills** →
`POST /api/skills/{skill_id}/run` → *Try it out*: pick a file, type the skill id
and options as JSON (e.g. `{"value_column": "amount"}`).

```bash
curl -s -F files=@samples/sales.csv -F 'params={"question":"average amount by store"}' \
  http://localhost:8000/api/skills/ask-your-data/run | python -m json.tool
```

## 4. Automated tests

```bash
pytest -q
```

`tests/test_data_skills.py` runs every skill on the sample data, and checks key
numbers (month-to-date totals, week-over-week math, partial periods,
ask-your-data answers) against plain pandas.
